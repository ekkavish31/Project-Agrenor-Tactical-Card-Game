- โลกคือ Agrenor ยุคปัจจุบัน

## 8. ข้อควรระวังสำหรับคนที่มาทำต่อ

- การแก้ `js/village-layout-v67.js` หรือ `js/game-settings.js` จะไม่ขึ้นในเบราว์เซอร์ที่ผู้ใช้เคยแก้ผังเอง จนกว่าเขาจะกด "!" ใน editor ถ้าเป็นไปได้ ให้ตั้งค่าเริ่มต้นในโค้ดแทน (ตัวอย่าง: ขนาดบ้านใหม่ใน `village-asset-edit.js`)
- ถ้าเปลี่ยน `world-gen` ให้สุ่มเพิ่มอีกจุดใน `tryGenerate` โลกที่ผู้เล่นเซฟไว้จะเปลี่ยนตาม ให้แยกเป็น random stream ของตัวเองแบบเดียวกับ `placeTowns`
- `WorldState.bind()` ผูก field แบบ non-enumerable เวลา `JSON.stringify` ของแผนที่โลกจะไม่บันทึก field เหล่านี้ (ตั้งใจให้เป็นแบบนั้น) ห้ามเขียนทับ `S.party = [...]` ด้วยอาร์เรย์ใหม่ เพราะ setter จะไปเขียนลงเซฟหลัก (ถ้าทำก็ได้ แต่ต้องรู้ว่ามันเกิดอะไรขึ้น)
- โค้ดหลายไฟล์เขียนแบบบรรทัดยาว เวลาแทรกคอมเมนต์ `//` กลางบรรทัด จะทำให้โค้ดหลังคอมเมนต์หายไปด้วย ให้ใช้ `/* */` แทน (เคยพลาดมาแล้วใน v94.00)
- หน้าใน iframe ต้องหา `GameHost` จาก parent ก่อนทุกครั้ง ห้ามอ่าน `localStorage` ของเซฟหลักตรง ๆ ตอนอยู่ในเกม เพราะ index จะเซฟทับ

- แต่ละรายการมีชื่อ คำอธิบาย บทบาท ความสัมพันธ์ และหลักฐาน `sourceRefs` (path + ID/symbol/หัวข้อ) พร้อม commit ที่ตรวจล่าสุด; หลักฐานต้องชี้ไปของจริงใน repo
- แยก `loreStatus`: confirmed / proposal / awaiting-lore ออกจาก `readiness`: concept / data / asset / integrated / tested; บันทึกความพร้อมเป็นรายส่วน เพราะมีภาพไม่เท่ากับใช้งานในเกมแล้ว
- แต่ละ event ระบุ required/optional dependencies พร้อมบทบาท เงื่อนไขก่อนเกิด ผลหลังจบ และสิ่งที่จำเป็นต่อ fallback; หากยังไม่มีตัวตนเป้าหมาย ให้เก็บ requirement ID/ชนิด/คำอธิบายโดยไม่สร้างตัวละคร Canon แทนเอง
- ข้อเสนอเชื่อมเรื่องมีสถานะ proposed / accepted / rejected พร้อมเหตุผลและหลักฐาน; การ accepted เป็นทิศทางออกแบบ ไม่ถือว่าผูกโค้ดหรือทดสอบแล้ว
- แยกข้อมูลออกแบบที่ commit ใน repo ออกจากประวัติการเล่นในเซฟของผู้เล่น; ไม่ push เซฟส่วนตัว
- Export เป็น JSON UTF-8 ที่มี schemaVersion, เวอร์ชัน/commit ต้นทาง และข้อมูลอ้างอิงครบ ใช้ diff ที่อ่านง่าย; import ตรวจโครงสร้าง/ID ซ้ำ/ชนิด/อ้างอิงก่อนใช้และไม่เขียนทับเงียบ ๆ
- การแก้ในเบราว์เซอร์หรือ localStorage อย่างเดียวยังไม่ถือว่าเซสชันถัดไปอ่านได้ ทูลต้องบอกสถานะ unsaved / exported / committed จากผลจริง และบันทึกผ่านระบบ push ของ repo หรือ export ให้ commit ได้ โดยไม่เก็บ token ลงไฟล์

### การวิเคราะห์สิ่งที่ขาดและการเสนอเชื่อมเรื่อง
รายงานต้องแยก missing (ไม่มี), incomplete (มีแต่ไม่ครบ), conflict (ข้อมูลขัดกัน), unknown (ยังไม่ได้ตรวจ), blocked-by-lore (รอการตัดสิน); ทุกข้อระบุ event/dependency ID, หลักฐาน, ผลต่อการเล่น, ลำดับความสำคัญ และขั้นถัดไป ห้ามตีความว่า “ไม่พบในทะเบียน” เท่ากับ “ไม่มีในเกม” หากยังไม่ได้ตรวจแหล่งจริง

ก่อนเสนอสร้างใหม่ ให้ค้นของเดิมจากบทบาท อาชีพ ที่อยู่ ความสัมพันธ์ ความรู้/แรงจูงใจ และเงื่อนไขเวลา เสนอ candidate พร้อมเหตุผล ข้อขัดแย้ง และสิ่งที่ต้องเพิ่ม ตรวจการใช้ NPC/สถานที่ซ้อนกัน สถานะย้าย/ตาย เงื่อนไขวนลูปหรือไปไม่ถึง และความพร้อมหลัง fallback; ไม่อ้างว่าตรวจเงื่อนไขสำเร็จหาก validator ยังไม่รองรับ

ตัวอย่างเชิงสมมติ (ไม่ใช่ event จริง): เหตุเหมืองผิดปกติต้องการฉากภายใน หลักฐาน และผู้แจ้งข่าว ทูลควรแยกว่าเหมืองมีแต่ฉากยังขาด ไอเทมยังไม่มี และ NPC คนงานเดิมอาจรับบทได้ โดยแสดง ID/หลักฐานจริงก่อนแนะนำ ไม่ตั้ง NPC ใหม่เป็นข้อเท็จจริง

## 14. เควสบทนำ "แพะของปิ๊บ / ฟักทองของฮิลด้า" → บทสอนต่อสู้ที่เล่าเรื่อง (9 พ.ย. 2026 · **รอบแรกทำแล้ว v98.331** · เหลือภาพจริง/ฉากหลัง/ปรับสมดุล ดูท้ายหัวข้อ)
**สถานะ:** ผู้ใช้เสนอไอเดียและตอบบางข้อแล้ว · ส่วนที่เป็นเนื้อเรื่อง/สิ่งมีชีวิตใหม่ **ยังไม่ใช่ canon** (ดูข้อ 14.3) · ห้ามเริ่มเขียนโค้ดจนกว่าผู้ใช้สั่ง
**ตอนนี้ในเกม** (`js/story-quests.js`): `goats` = แพะของ **ปิ๊บ** 3 ตัววิ่งหนี คลิกเก็บแล้วพากลับคืน (+15 เหรียญ) · `pumpkin` = เก็บฟักทองสุก 3 ลูกที่ไร่ฮิลด้า แล้วดูแลฟักทองประกวด · `contest` = แบกฟักทองไปลาน — ทั้งหมดเป็น "คลิกวัตถุ" ไม่มีระบบต่อสู้

### 14.1 สิ่งที่ผู้ใช้ตัดสินแล้ว (จากการคุยเมื่อ 9 พ.ย. 2026)
- ใช้เควสนี้เป็นโอกาสแนะนำระบบต่อสู้ แทนการคลิกวัตถุ · แนวเล่าเรื่องผ่านการต่อสู้แบบ Dark Dungeon (ตัดฉากเข้าสู่สนามย่อย)
- **แพะ:** ยังเป็นของ **ปิ๊บ** (ตรงกับ canon วันเตรียมงานแรก) · ตอบโต้ได้บ้างแต่ไม่เจ็บมาก
- **ฟักทอง:** มีชีวิตได้ · มี **3 ลูก** แต่ละลูกมี HP พอให้รับการโจมตีได้ **ประมาณ 2–3 ครั้ง** (ที่เคยบันทึก "HP 3" ถูกแทนด้วยข้อนี้แล้ว) โจมตีจนหมดแล้ว "เด้งเป็นฟักทองให้เก็บ" · ใน 3 ลูก **มี 1 ลูกเท่านั้นที่วิวัฒน์เป็นบอส** (เป็น event) บอสนี้เดินและโจมตีได้ ต่อสู้ได้
  - *ข้อเสนอตั้งค่า:* กำหนด HP ฟักทองเป็น "จำนวนครั้งที่ตีปกติของตัวเอก" (เช่น 2–3 ครั้ง ≈ HP = 2.5 × ความเสียหายตีปกติ) ไม่ผูกตัวเลขตายตัว แล้วปรับตอนทดลองเล่น
- ระหว่างเก็บฟักทองมี **แมลงศัตรูพืช** มารบกวนเล็กน้อย
- **ตัวเอกทั้งสองคน (พี่ชาย + น้องสาว) เป็น "อมตะเลือด" ตลอดสองเควสนี้ (แพะ + ฟักทอง):** เลือดลดได้แต่ **ไม่ต่ำกว่า 1** → ไม่ล้ม ไม่แพ้ ไม่ติดบาดเจ็บ (ระบบ `js/injury.js` ทำงานตอนล้มเท่านั้น) · บทสอนจึงไม่มีสถานะ "แพ้" ของตัวเอก
  - *ข้อเสนอทำ:* ธงต่อฉาก `st.opts.immortal = ['hero','sib']` แล้วกันเลือด ≥ 1 ที่จุดลดเลือดทั้งหมดใน `js/flat-battle.js` — `hurt()` (บรรทัดที่ `tgt.hp = Math.max(0, tgt.hp - d)` ~224) · พิษ/DoT (~215) · ความเสียหายจากการตก/ผลัก (~454/598) · ตรวจให้ตรวจ "ชนะ/แพ้" และ HUD ไม่เข้าใจผิด (เลือดค้างที่ 1) · ฉากอื่นนอกสองเควสนี้ไม่ใช้ธงนี้
- หมายเหตุ canon: `docs/lore/CURRENT-ERA-CANON.md` Part A วันเตรียมงานแรกบอกแค่ "ช่วยจับแพะของปิ๊บ เก็บฟักทองและดูแลฟักทองประกวดของฮิลดา" · บอสฟักทอง/แมลงศัตรูพืช **เป็นเหตุการณ์ใหม่ที่ผู้ใช้เพิ่ม ไม่ได้อยู่ใน canon เดิม** (ไม่ขัดแต่ยังไม่ได้บันทึกเข้า canon — ผู้ใช้ตัดสินเองว่าจะยกเข้า Part A หรือไม่) · **ต้องไม่กระทบ** ข้อกำหนดเดิมที่ว่าผลประกวดขึ้นกับจำนวนวันที่ช่วยฮิลดา (ห้ามสรุปว่าฮิลดาชนะตายตัว) และฟักทองประกวดเป็นคนละลูกกับบอส

### 14.2 ร่างแนวทาง (ข้อเสนอ — รอผู้ใช้ยืนยัน)
1. **แพะ → สอนเดิน/ระยะ/ทิศหน้า-หลัง/ความสูง:** แพะหนีทุกเทิร์น + ตอบโต้เบาๆ · ผู้เล่นต้อนแล้วจับ (เป้าหมายแบบ "จับ" ชนิดใหม่ — ข้อมูลเป้าหมายพิเศษมีอยู่แล้ว: หนีออก/ป้องกันธง)
2. **เก็บฟักทอง → สอนโจมตี/เลือกเป้า/ธาตุ:** เก็บ 3 ลูก มีแมลงศัตรูพืชรบกวนเล็กน้อย (บทสอนโจมตีเป้าเล็ก) → ฟักทองหนึ่งลูกวิวัฒน์เป็นบอส (event ตายตัว ไม่สุ่ม)
3. (ถ้าเอา) วันประกวด → สอนตั้งรับ
- **ของเดิมที่ใช้ต่อได้:** ระบบวิวัฒน์ในสนามรบ (v98.58 `evolveCheck`/`evolveNow` ใน `js/flat-battle.js` + ฉากเปลี่ยนร่าง/ออร่าใน `town-battle.js`) · โหมดสอน `?tut=` (coach ทีละข้อ) · วิธีฝังสนามรบเป็นฉากซ้อนของบทนำ (`startRaid` ใน `story-quests.js` ใช้ `village-town.html?battle=1&embed=1`)
- **ต้องเพิ่ม:** (ก) วิวัฒน์แบบ "บังคับเกิดตามเงื่อนไข event" (ระบบเดิมสุ่มตามโอกาสซ่อน) (ข) เป้าหมายแบบ "จับ" + AI แพะหนี/ตอบโต้เบา (ค) ยูนิตใหม่: แพะ · ฟักทอง · บอสฟักทอง · แมลงศัตรูพืช (ภาพหลายทิศ ท่ายืน/เดิน/โดนตี) (ง) ข้อมูลฉาก + กล่องคำสอน (จ) ทางออกถ้าแพ้ = ลองใหม่ไม่มีโทษ (ยังไม่ยืนยัน — ข้อ 14.3)

### 14.3 ยังรอผู้ใช้ตอบ / ต้องตรวจก่อนเริ่ม
1. ฟักทองอีก 2 ลูกที่ไม่วิวัฒน์ (รับตี 2–3 ครั้ง) เป็นเป้านิ่งไม่ขยับและไม่โจมตี ใช่ไหม · ~~HP~~ ตอบแล้ว (14.1) · ที่ยังไม่ได้กำหนด: **บอสฟักทอง** HP/พลังโจมตี/ท่า อยากให้อยู่ระดับไหน (ผมเสนอค่าตั้งต้นให้ได้) · ลูกไหนใน 3 ลูกที่วิวัฒน์ (ตำแหน่งตายตัว หรือสุ่มต่อฉาก)
2. **เงื่อนไขวิวัฒน์ของ event:** เกิดตอนไหน เช่น หลังเก็บลูกที่ 2/3 · เมื่อโจมตีฟักทองลูกที่กำหนด · เมื่อแมลงมารบกวนถึงจำนวนหนึ่ง · หรือเกิดตอน HP ของลูกนั้นเหลือ 1 (ใช้ระบบวิวัฒน์เดิม แต่บังคับเกิด)
3. แมลงศัตรูพืช: กี่ตัวต่อฉาก · หน้าตา (ผู้ใช้สร้างภาพเอง) · ทำอะไร (กัดเบาๆ/ขโมยฟักทอง/บังทาง)
4. ตัดฉากเข้า: สนามรบเต็มจอ หรือฉากย่อใช้ HUD การ์ดเดียวกัน
5. ~~แพ้~~ ตัวเอกเป็นอมตะเลือดแล้ว (14.1) จึงแพ้ไม่ได้ · ที่ยังต้องตอบ: ถ้าผู้เล่น *ไม่ทำเป้าหมายสำเร็จ* ในฉาก (เช่น แพะหนีไปหมด ฟักทองบอสยังไม่ล้ม) ให้ฉากจบยังไง — วนต่อจนกว่าจะสำเร็จ หรือมีเทิร์นจำกัดแล้วเริ่มใหม่
6. ภาพที่ต้องมี: แพะ · ฟักทอง (นิ่ง/โดนตี/เด้ง) · บอสฟักทอง (หลายทิศ เดิน/โจมตี/โดนตี/ล้ม) · แมลง — ผู้ใช้สร้างเอง หรืออยากให้ผมเสนอรายการภาพก่อน
7. ลำดับเริ่มทำที่แนะนำ: ฟักทอง + แมลง + บอสวิวัฒน์ (ใช้ระบบวิวัฒน์เดิมแบบบังคับ) ก่อน แล้วค่อยแพะ (ต้องทำ AI หนี/จับเพิ่ม)

## 19. Asset แบบ local ระหว่างพัฒนา (10 พ.ย. 2026 · v98.365 · ทำแล้วรอบแรก)

ตัดสินใจ: ตอนนี้เน้นพัฒนา ยังไม่เปิดให้ใครเล่น → ไม่ทำระบบดาวน์โหลด asset ลงเครื่องผู้เล่น และไม่ย้ายโฮสต์ (ดูหมวด 18)
- เปิดเกมด้วย `node tools/dev-server.cjs --assets <โฟลเดอร์ asset ในเครื่อง>` (พอร์ตเริ่มต้น 8080 · `--port` เปลี่ยนได้)
  - คำขอ `/assets/**` ค้นในโฟลเดอร์ local ก่อน ไม่มีค่อยใช้ `assets/` ใน repo · แยก `html/js/data` ไว้ใน repo ตามเดิม · origin เดียว ไม่มีปัญหา CORS/canvas
  - ค่าที่ editor เก็บ (สเกล ตำแหน่ง manifest เลย์เอาต์) ก็ overlay ได้: `/data/**` และ `/js/asset-manifest.js` ค้นใน `<โฟลเดอร์>/data`, `<โฟลเดอร์>/js` ก่อน แล้วค่อยถอยไป repo · ต้องให้ Studio เขียนลงโฟลเดอร์นั้น (ตรวจว่า `saveManifest` เขียน path ใด)
  - โฟลเดอร์ชี้ได้ทั้งแบบ `<root>/assets/...` และชี้ที่ `assets` ตรง ๆ · ไม่ cache เลย (แก้ภาพแล้ว F5)
  - บน localhost เกมไม่ลงทะเบียน `sw.js` และล้างแคชเก่าให้ (`js/game-version.js`)
- ยังเก็บ `assets/` ไว้ใน repo (ไม่ได้ลบ) เพราะบน GitHub Pages ผู้เล่นต้องใช้ · สำเนา local: `cp -r assets /path/to/local-assets`
- ค้าง: (1) ตัดสินใจเมื่อไรจะถอด `assets/` ออกจาก repo (ต้องมีที่โฮสต์ asset ก่อนเปิดให้คนเล่น → ดูหมวด 18) (2) สคริปต์ตรวจ manifest ↔ ไฟล์จริง และ contact sheet ต่อ entity ให้ AI/คน เห็นภาพรวม (3) ให้ Asset Studio เขียนลงโฟลเดอร์ local เดียวกับที่ dev-server ใช้ (ตอนนี้เลือกโฟลเดอร์เอง)
