# ฉากต่อสู้ตายตัว (Set-Piece) — วิธีออกแบบและเขียนฉากใหม่

> ใช้กับบอสและทางแยกสำคัญ ต่างจากการต่อสู้ทั่วไป (สนามสุ่มจาก seed วางหน่วยตามมุม) — ฉากตายตัว **ไม่สุ่มเลย** เหมือนฉากไร่ฟักทอง แต่ให้ศัตรูได้เปรียบและบังคับให้ผู้เล่นคิดกลยุทธ์
> โค้ด: `js/set-pieces.js` · ใช้ผ่าน `?scene=<id>` ที่ `battle-field.html` (world-map.js ส่งให้เมื่อ `battle(foe, dang, { scene })`)

## ฉากที่มีแล้ว
| id | ใช้ที่ไหน | แนวคิด | ศัตรูได้เปรียบอย่างไร | คำตอบของผู้เล่น |
|---|---|---|---|---|
| `hungerPit` | บอสก้อนหิว (ก้นเหมือง · ตอนจบ) | **ตัดอาหารมัน** (Canon A12): ปมหิว 3 จุดป้อนก้อนหิว | บอสยึดที่สูงระดับ 2 · เริ่มก่อน · ดาเมจเหลือ 50% ตราบที่ยังมีปม + ฟื้นเลือด 4/ปม/รอบ · คลื่นสัตว์รอยหมองทุก 4 รอบจากอุโมงค์เหนือสองทางขนาบ | ตัดปมก่อน (ซ้าย ขวา และกลางห้องที่เป็นโคลน) · ใช้เศษหิน/เสากันคลื่น · ตัดปมครบ = บอสเสียหลัก 1 ตา |
| `convoyPass` | ขบวนนักโทษ (สะกดรอยแล้วพลาด) | ซุ่มโจมตีที่ช่องเขา | ผู้คุมยึดที่สูง · 5 ตัวตั้งแนวอยู่แล้ว + หัวหน้า · แตรสัญญาณ 2 ตัวเรียกโจรมาเสริมทุก 3 รอบ (ไม่เกิน 5) | แยกคนอ้อมไปทำลายแตรที่ปลายแอ่งเหนือ/ใต้ ระหว่างที่ช่องกลางตรึงไว้ · ตัดแตรครบ = หยุดกำลังเสริม |

| `campDefense` | ผู้อพยพที่ป่วย (เลือกพยุงเธอ) | ป้องกันผู้ป่วยกลางค่ายที่ล้อมรั้ว (ช่องเปิด 4 ช่อง) 8 รอบ | มาสามทิศ คลื่นละมากขึ้น (1→1→2→2) · ตัวไหนเหยียบช่องผู้ป่วย = แพ้ | ใช้ตัวคนอุดช่องรั้ว (เหนือ/ตะวันออก/ใต้) · ลังกำบังหลังช่อง · ฆ่าให้หมดก่อนคลื่นถัดไป |
| `moonGuard` | พิธีคืนจันทร์ม่วง (เลือกเฝ้า Mip) | ป้องกัน Mip บนแท่นหิน 7 รอบ | มาสามทาง เสาหินบีบเป็นช่องแคบ · ถอยได้แต่ด้านใต้ | ปลอกคอ Mip ส่องแสงรัศมี 2 ทำดาเมจ 16 ที่รอบ 3 และ 6 (ประกาศล่วงหน้า) — ล่อศัตรูเข้ามาก่อนถึงจังหวะ |

## โครงสร้างของฉาก (`SCENES[id]`)
- `R` / `map`: สนามวาดด้วยโค้ด (`makeGrid(R, [[ตัวอักษร, u0, v0, u1, v1], …])`) พิกัด −R…R · `#` กำแพง · `.` พื้น · `+` ที่กำบัง (−30%) · `~` โคลนช้า · `1` `2` พื้นสูง (ก้าวขึ้นได้ทีละ 1 ระดับ) · `b` กำแพงกระดูก — `field-host.js` ใช้แทนสนามสุ่ม (ความสูงแน่นอนด้วย)
- `hero` / `allies` / `enemies`: ตำแหน่งเริ่มทุกตัว · ศัตรูมี `hp` (คูณจากค่าฐานของ MON × สเกลเลเวล) · `boss:true` = ใช้ท่าพิเศษของบอส · `ct` = จังหวะเริ่ม (ศัตรูเริ่มก่อน) · `kind` ต้องมีใน `MON` (`town-battle.js`) — วาดด้วยโค้ดได้ใน `js/code-monsters.js`
- `obj: { type: 'boss' }`: ล้มบอส = ชนะ แม้ลูกน้อง/ปม/แตรยังอยู่ · `obj: { type: 'defend', turns, cells }`: ป้องกันช่องให้ครบกี่รอบ (ศัตรูเหยียบช่อง = แพ้) · ฉากที่มีคลื่น `waves.count` ยังไม่ชนะแม้ศัตรูตอนนี้หมด (`rules.pending`) · `pulses [{ rounds, at, radius, dmg, text, warn }]` ชีพจรทำดาเมจรอบจุดตามรอบ · `noFlee: true`: ไม่มีทางหนี · ตัวอักษรแผนที่เพิ่ม `t` เต็นท์ `f` รั้ว `p` เสา
- `anchorKind` + `rootShield` + `rootHeal`: วัตถุที่ต้องทำลาย (ปม/แตร) — ถ้ามี `rootShield` บอสเจ็บน้อยลงจนกว่าจะตัดครบ · `rootHeal` ป้อนเลือดบอส · `waves { first, everyRounds, mouths, kind, per, cap, needAnchor, capBy }` คลื่นเสริมกำลัง (ประกาศล่วงหน้า 1 รอบ; `needAnchor` = ตัดวัตถุครบแล้วคลื่นหยุด)
- `intro` / `hints`: **แผงกติกา** ที่ขึ้นก่อนเริ่มสู้ (อ่านได้ซ้ำจากปุ่ม 📜 กติกาฉาก มุมซ้ายล่าง) และคำใบ้ที่ปรากฏตามรอบ — **บอกกติกาให้ผู้เล่นอ่านออกก่อน ไม่ใช่ให้เดา**

## หลักการออกแบบ (ให้ "ใช้สมอง" ไม่ใช่แค่ "ยาก")
1. มีกติกาซ่อนที่ **ค้นพบแล้วเปลี่ยนวิธีเล่น** (ตัดปม · ตัดแตร) และบอกใบ้ตั้งแต่รอบ 1–2
2. ศัตรูได้เปรียบเชิงตำแหน่ง/จำนวน/จังหวะ ไม่ใช่แค่ตัวเลขสูง
3. มีทางเลือกอย่างน้อย 2 ทาง (ส่งคนไปตัดปมซ้าย/ขวา · อ้อมแอ่งไปตัดแตร · ตั้งแนวที่เสาหิน)
4. ชนะได้โดยไม่ต้องล้างทุกตัว (เป้าหมายบอส) แต่แพ้เพราะไม่อ่านกติกาจะเห็นสาเหตุชัด (ข้อความบนจอบอกทุกครั้งว่าปม/แตรกำลังทำอะไร)
5. **ตรวจด้วยตัวจำลองก่อนปล่อย**: `SCENE=<id> BOT=naive|smart node tools/simulate-scene.cjs 100` — ฉากบอสควรให้บอทที่ไม่อ่านกติกาชนะ ≤ ~10% และบอทที่อ่านกติกาชนะประมาณ 45% (บอทไม่ใช้ไอเทม/ไม่ประสานเพื่อน ผู้เล่นจริงควรเก่งกว่า)
6. เทสต์ `node tools/test-set-pieces.cjs`: แผนที่ถูกต้อง (เดินถึงกัน ก้าวสูงต่ำ ≤ 1) · ไม่สุ่ม (สร้างสองครั้งเหมือนกัน) · กติกาทำงานจริง
