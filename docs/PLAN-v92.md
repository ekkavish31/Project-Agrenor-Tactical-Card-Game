# แผนพัฒนา Project Agrenor 2.5D (ร่าง 28 ต.ค. 2026 · repo v92.01)

แผนฉบับนี้แทนที่ M1 ใน `docs/ROADMAP.md` (แกนเกม) ส่วน M2-M7 เดิมยังใช้อ้างอิงได้

## ภาพรวมและหลักการ

เกมคือเจ้าของร้านที่ออกผจญภัยหาของเองจากดันเจี้ยน แล้วเอาเงินมาพัฒนาเมืองให้แข็งแกร่งพอรับมือภัยคุกคาม การต่อสู้เป็นการ์ดบน grid ภาพ 2.5D isometric มุมมองทิศเดียว และหมู่บ้านถูกวางอยู่ใน region หนึ่งของ world map Agrenor ที่ถูกหมอกดำคลุมไว้

หลักการทำงาน:

- สร้างจากหน่วยเล็กสุดขึ้นไป ชั้นล่างต้องนิ่งก่อนต่อชั้นบน
- ทุกระบบต้องป้อนกลับเข้าลูปหลัก ระบบที่ไม่ป้อนอะไรกลับเข้าลูปให้ตัดหรือเลื่อนไปทีหลัง
- เก็บกวาดก่อนเพิ่มฟีเจอร์ (lean-first)
- ข้อมูลเกม (entity, ไอเทม, การ์ด, โซน) เป็นไฟล์ JSON แยกจากโค้ด

## ลูปหลักและ 3 เสาหลัก

ลูปหลัก: ดันเจี้ยน → ของดรอป → คราฟและขายในร้าน → เงินและชื่อเสียง → พัฒนาเมือง → ปลดล็อกดันเจี้ยนที่โหดขึ้นและรับมือภัยคุกคามได้ แล้ววนกลับ

3 เสาหลักที่ทำก่อน:

1. **ต่อสู้แบบการ์ดบน grid** ฮีโร่ มอน และพันธมิตรเดินและตีกันบน grid เดียวกับ map editor
2. **ดันเจี้ยนสุ่ม** ต่อห้อง prefab ที่สร้างใน editor เข้าด้วยกัน มีของดรอปและความเสี่ยงตอนถอย
3. **ร้านและคราฟ** เอาของจากดันเจี้ยนมาคราฟ ตั้งราคา และขาย

ระบบที่เหลือ (เมือง ฟาร์ม การเมือง อีเวนต์ คู่แข่ง โจรบุกเมือง) ต่อเข้าเสาหลักทีหลังตามลำดับใน Roadmap

## ชั้นการพัฒนาจากหน่วยเล็กสุด

| ชั้น | หน่วย | ผ่านเมื่อ |
| --- | --- | --- |

| 2 | Asset + footprint + ทางเข้า | ของชนกันไม่ได้ footprint ปรับได้ ทางเข้าเป็นช่องที่ตัวละครเดินผ่าน |

## World map และหมอกดำ

หมู่บ้านอยู่ใน region หนึ่งของ world map Agrenor และถูกหมอกดำคลุมรอบ ๆ ผู้เล่นเปิดแผนที่ทีละโซนผ่านข้อมูล การสนทนา ไอเทม หรือแผนที่ที่บอกตำแหน่ง หน่วยเล็กสุดคือ **โซน** ที่มี 3 สถานะ:

1. **ซ่อน (หมอกดำ)** มองไม่เห็นและเดินทางไปไม่ได้
2. **ข่าวลือ** รู้ตำแหน่งคร่าว ๆ เห็นเป็นเงาพร้อมเครื่องหมาย ? ไปได้แต่ไม่รู้ว่ามีอะไร
3. **เปิดแล้ว** เห็นเต็มและเข้าดันเจี้ยน เควส ร้านค้าได้

วิธีเปิดโซน:

| แหล่ง | ผล |
| --- | --- |
| คุยกับ NPC (ชาวเมือง พ่อค้าเร่) | ซ่อน → ข่าวลือ |
| หาข้อมูล (โรงเตี๊ยม ห้องสมุด ขุนนาง ใช้เงินหรือความสัมพันธ์แลก) | ซ่อน → ข่าวลือ |
| ไอเทม (เศษแผนที่ เข็มทิศ กล้องส่องทางไกล) | เปิดเป็นรัศมีหรือเป็นโซน |
| แผนที่ที่บอกที่ตั้ง (ต่อยอดจากไอเทม "แผนที่สมบัติเก่า" ที่มีอยู่แล้ว) | เปิดโซนเดียวพร้อมเครื่องหมาย |
| เคลียร์ดันเจี้ยนในโซน | เปิดโซนข้างเคียง |
| อาคารในเมือง (หอสังเกตการณ์ ประภาคาร) | ดันหมอกรอบหมู่บ้านถาวร |
| เนื้อเรื่องหลักและบอส | เปิดหลายโซนพร้อมกัน |

หมอกมีผลกับเกมด้วย ยิ่งอยู่ลึก มอนยิ่งโหดและของดรอปยิ่งดี และถ้าเมืองโดนบุกอาจทำให้หมอกคืบกลับมา

ที่มีอยู่แล้วใน repo: การผจญภัยเป็นกราฟโหนดต่อพื้นที่ (เริ่ม → บอส) ใน `js/adventure-data.js` พื้นที่เดิม (ป่า เหมือง ภูเขาหิมะ ชายฝั่ง บึง ซากวิหาร) ย้ายมาเป็นโซนบน world map ได้โดยไม่ต้องรื้อ ส่วน world map และหมอกยังไม่มี

การนำไปใช้: เก็บเป็นรายการโซนที่เปิดแล้วในเซฟ มีฟังก์ชันเดียว `revealZone(id, แหล่งที่มา)` แล้วต่อแหล่งเปิดทีละอย่าง เริ่มจากแผนที่สมบัติและการเคลียร์ดันเจี้ยนซึ่งง่ายสุด

## ระบบต่อสู้

**เลือกแบบ B:** grid แบนล้วนแบบ Fire Emblem ไม่มีระบบความสูง ภาพยังเป็น 2.5D แต่ความต่างของแต่ละพื้นที่มาจากชนิดของช่อง (terrain) แทน

| ทางเลือก | ข้อดี | ข้อเสีย |
| --- | --- | --- |
| A. Octopath-style บนฉากจาก editor (มีระบบความสูงเต็ม) | แมพที่สร้างมีความหมายในการต่อสู้ | อ่านตำแหน่งและระยะยาก ต้องทำ logic ความสูงซับซ้อน |
| B. Fire Emblem-style grid แบน (เลือก) | ทำเร็ว อ่านง่าย เข้ากับการ์ด | ภาพ 2.5D ไม่มีผลกับการเล่น |
| C. Hybrid | ได้ความชัดเจนของ grid แบนและความรู้สึก 2.5D | ต้องกำหนดให้ชัดว่าความสูงมีผลแค่ไหน |

แนวทางที่เลือก (B พร้อม terrain):

- ไม่มีระบบความสูง ทุกช่องอยู่ระดับเดียวกัน ความต่างมาจากชนิดของช่อง (terrain) ที่ให้ผลต่อการเดินและการต่อสู้
- มุมมองทิศเดียว ไม่ต้องหมุนกล้อง ของสูงบังได้ตามชั้นภาพ
- ใช้ฉากเดียวกันจาก map editor ทั้งดันเจี้ยน ป่า และเมืองโดนบุก
- grid 1x1 ที่กำลังทำอยู่เป็นฐานของการต่อสู้ ไม่ต้องมีสองระบบ
- การ์ดเป็นแกน: อาวุธและไอเทมที่คราฟหรือดรอปกลายเป็นการ์ดของฮีโร่

สถานะปัจจุบัน: ระบบต่อสู้เดิม (`js/tactics-core.js`) ใช้ grid ของตัวเองและผ่านเทสต์กฎ 10 ข้อและเทสต์การ์ด 11 ข้อ แต่ยังไม่ได้ใช้ฉากจาก editor

ข้อมูล terrain: editor เก็บค่ารายช่องไว้แล้ว (เดินผ่านได้หรือไม่ ระดับจม ความทึบ) จึงต่อยอดเป็นชนิดช่องที่ให้ผลต่างกันได้โดยไม่ต้องสร้างระบบแยก ตัวอย่างผลที่เป็นไปได้ (ยังไม่ตัดสินใจ): เดินช้าลง ที่กำบัง กีดขวาง ดาเมจต่อเทิร์น

| เฟส | งาน | ผ่านเมื่อ |

## สถานะ repo งานเก็บกวาด และความเสี่ยง

ตรวจเมื่อ 28 ต.ค. 2026 ที่ v92.01 ผลเทสต์ที่รันในโหนด (ยังไม่ได้เปิดเกมในเบราว์เซอร์): กฎต่อสู้ 10 ข้อ การ์ด 11 ข้อ terrain และ fence ผ่านหมด ส่วน `tools/test-grid-p1.cjs` และ `tools/test-footprint.cjs` พัง น่าจะเป็นเทสต์เก่าหลังเปลี่ยนกฎ grid และ footprint แต่ยังไม่ได้ยืนยัน

งานเก็บกวาดที่ค้าง:

- ซ่อมหรืออัปเดตเทสต์ grid และ footprint ให้ตรงกับกฎปัจจุบัน
- แปลง PNG ที่เหลือ 240 ไฟล์ (ประมาณ 144MB) เป็น WebP ทั้ง repo หนัก 661MB
- อัปเดต README ที่ยังเขียนว่า v34 และยุบ `docs/TODO.md` (64KB) ที่เต็มรายการเก่าให้เหลือฉบับเดียว
- แยกไฟล์ใหญ่ `js/village-layout-v67.js` (3,336 บรรทัด) และ `js/village-asset-edit.js` (3,100 บรรทัด) เมื่อถึงคิว
- แทนที่ M1 ใน `docs/ROADMAP.md` ด้วยแผนฉบับนี้

ความเสี่ยง:

- ขอบเขตบานเร็ว เพราะรายการระบบที่อยากได้ยาวมาก ให้ยึด 3 เสาหลักก่อน
- เปลี่ยนกฎ grid และ footprint หลังสร้างทับไปแล้วจะกระทบทุกชั้น
- โค้ดที่ AI เขียนไว้ในบางส่วนอ่านยาก การรื้อโดยไม่มีเทสต์ที่เชื่อถือได้เสี่ยงทำของเดิมพัง

## คำถามที่ต้องเคาะ

- [ ] terrain ของแต่ละช่องมีชนิดอะไรบ้างและให้ผลต่างกันอย่างไร (เดินช้า ที่กำบัง กีดขวาง ดาเมจต่อเทิร์น) ตัดสินแล้วว่าใช้ grid แบนล้วน (B) ไม่มีความสูง
- [ ] แต่ละฝ่ายมีกี่หน่วย และแมตช์ยาวประมาณกี่เทิร์น
- [ ] การ์ดได้มาจากไหน: เลือกก่อนแมตช์ ได้ระหว่างทาง หรือได้จากหมู่บ้าน
- [ ] ผู้เล่นคุมฮีโร่ตัวเดียว (อัศวิน Agrenor) หรือคุมทั้งทีม
- [ ] world map แบ่งเป็นช่องตาราง (เปิดทีละช่อง เซฟง่าย แนะนำ) หรือพื้นที่รูปทรงอิสระ
- [ ] โซนที่เป็นหมอกดำเข้าไม่ได้เลย หรือเข้าได้แต่เสี่ยง
- [ ] region แรกที่หมู่บ้านอยู่ชื่ออะไร และมีกี่โซนในเวอร์ชันแรก
