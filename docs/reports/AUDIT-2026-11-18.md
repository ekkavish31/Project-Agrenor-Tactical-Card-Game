### 2.2 [P0] เงาขอบขาวของตัวที่โดนบัง — ช้าลง 20 เท่า
- **หลักฐาน:** `js/depth-style.js:70` ตั้ง `g.filter = 'drop-shadow(1.5px 0 0 #fff) drop-shadow(-1.5px …) ×4'` แล้ววาดตัวละครทุกเฟรมที่ตัวละครอยู่หลังของสูง (`coverDraw` → `ghost`) · หัวลูกศรบนหัว (`js/head-arrow.js:76`) และ `town-art.js:73` ก็ถูกวาดผ่านฟิลเตอร์นี้ด้วย
- ทดลองในตลาด (ตัวเอกเกิดหลังเสาธงพอดี): **2.8 fps** → ปิดฟิลเตอร์อย่างเดียว **59.2 fps**
- เหตุ: ฟิลเตอร์ canvas สร้างเลเยอร์ขนาดเท่าทั้งจอแล้วเบลอ/เลื่อน 4 รอบ ต่อการวาด 1 ครั้ง (บนเครื่องที่ไม่มี GPU หนักมาก บน GPU ก็ยังเป็น 4 pass เต็มจอ)
- **ข้อเสนอ:** สร้าง "ภาพเงาขอบ" ของแต่ละเฟรมท่าไว้ล่วงหน้าครั้งเดียว (offscreen canvas ขนาดเท่าตัวละคร: วาดตัวละคร 4 ทิศเลื่อน 1.5px แล้วระบายขาวด้วย `source-in`) เก็บแคชตาม ภาพ+ขนาด แล้ววาดเป็นภาพธรรมดา — ได้ภาพเหมือนเดิม ค่าใช้จ่ายเท่าการวาดภาพ 1 ครั้ง · และย้ายจุดเกิดในตลาดออกจากหลังเสาธง

### 2.3 [P1] โหลดครั้งแรกหนักเกิน
- หน้าแรก (ยังไม่กด New Game) โหลด **524 ไฟล์ · 46 MB**: ภาพ webp 32 MB, JS 11 MB, mp3 2.7 MB · iframe หมู่บ้านโหลดพร้อมกันตั้งแต่หน้าแรก (26.7 MB)
- `js/asset-manifest.js` = **3.4 MB** โหลดใน 10 หน้า (หน้าแรก + iframe = 2 รอบ) — ส่วนใหญ่เป็นรายการเฟรมแอนิเมชันที่ใช้เฉพาะ Asset Studio
- ภาพใหญ่ที่สุดที่โหลดตอนเปิด: `assets/village-town/temple.webp` 1.4 MB, `assets/scenes/area-forest.webp` 0.9 MB, `assets/v03/village-map.webp` 0.6 MB
- **ข้อเสนอ:** (ก) หน่วงการโหลด iframe หมู่บ้านจนกด New Game/Continue (ข) แยก manifest เป็น "ฉบับเล่น" (เฉพาะ asset ที่ status final + ใช้จริง) กับ "ฉบับเอดิเตอร์" (ค) preload เฉพาะภาพในจอแรก ที่เหลือโหลดตอนว่าง (ง) ตั้งเป้า < 10 MB ก่อนผู้เล่นกดครั้งแรก

### 2.4 [P1] สนามรบ 50 ms/เฟรม (≈20 fps ในเครื่องไม่มี GPU) — ต้นทุนกระจาย ไม่มีจุดเดียว
- CPU profile: วาดภาพ (native) 85% · `gridHidden` (`js/town-battle.js:1440`) 3.4% · `occOf/occBuild` (`js/field-host.js:380–390`) 2.9%
- ต่อเฟรม: เติมสีแบบ `lighter` ≈ 265 ครั้ง (`js/ground-art-code.js:69` และ `js/town-battle.js:1928–1932`) · ภาพหญ้าสูง `assets/tactics/ground/tallgrass.webp` 640×376 ถูกย่อวาด 33 ครั้ง/เฟรม (ต้นฉบับใหญ่กว่าที่แสดงราว 88 เท่า)
- ทดลองปิดทีละอย่าง: ปิด tilt-shift ไม่ต่าง · ปิด `lighter` 19.3 → 21 fps · ปิดหญ้าสูงไม่ต่าง → ต้องลดหลายจุดพร้อมกัน
- **ข้อเสนอ:** แคชพื้น/หญ้า/เอฟเฟกต์ที่ไม่ขยับลง offscreen canvas วาดใหม่เฉพาะตอนกล้องเปลี่ยน · ทำภาพย่อ (mip) ของ prop เล็กไว้ล่วงหน้า · คำนวณ occlusion ใหม่เฉพาะตอนยูนิตย้าย · ติดเครื่องวัด ms/เฟรม ใน `?perf=1` เพื่อให้ผู้สร้างวัดบนเครื่องจริง

### 2.5 [P2] long task ตอนเข้าหมู่บ้านยาว 1.8 วิ
- `village-town.html` มี long task 39 ครั้ง ยาวสุด 1,816 ms (ช่วงโหลด/ถอดรหัสภาพ + สร้างแคชพื้น) · หมู่บ้านวาดภาพ 56 ล้านพิกเซล/เฟรม (ตลาด 5 ล้าน)
- **ข้อเสนอ:** แบ่งงานสร้างแคชเป็นช่วงสั้น (idle callback) แสดงจอโหลดระหว่างนั้น · ใช้ `createImageBitmap` ถอดรหัสภาพนอกเธรดหลัก

### 2.6 [P2] แสงกลางวัน/กลางคืน (DayLight) วาดเต็มความละเอียดทุกเฟรม
- `js/day-light.js:47` สร้าง light map เท่าจอแล้ว `multiply` ทั้งจอทุกเฟรม แม้แสงตะเกียงจะจางจนมองไม่เห็น (เช้า 08:01 lamps = 0.07 ยังวาดตะเกียงครบ)
- **ข้อเสนอ:** วาด light map ที่ ½ ความละเอียดแล้วขยาย (แสงนุ่มอยู่แล้ว มองไม่ต่าง) · ข้ามตะเกียงเมื่อแรง < 2% · อัปเดตแสงกะพริบ 15 ครั้ง/วิ แทนทุกเฟรม

### 2.7 [P2] หน้าแรกเรียก GitHub API ทุกครั้งที่เปิด
- `js/title-screen.js:160` เรียก `api.github.com/…/commits/main` และ `git/trees/main?recursive=1` — ระหว่างตรวจได้ **403 rate limit** (GitHub ให้ 60 ครั้ง/ชม./IP โดยไม่ล็อกอิน)
- **ข้อเสนอ:** เรียกเฉพาะโหมดผู้สร้าง/เอดิเตอร์ หรือเก็บผลไว้ 1 ชม. · ผู้เล่นทั่วไปไม่ต้องเรียกเลย

### 2.8 [P2] เลข `?v=` ไม่ตรงกันข้ามหน้า (14 ไฟล์)

## 3. ด้านความถูกต้อง/ความสอดคล้องของ UI

### 3.1 [P1] ตัวเลือกในตั้งค่าที่ไม่มีผล
- `js/settings.js:7` ตั้ง `window.GAME_DIFFICULTY` และ `window.GAME_SPEED` · แต่ระบบต่อสู้ปัจจุบัน (`flat-battle.js`, `town-battle.js`, `field-host.js`) **ไม่อ่านทั้งสองค่า** — มีแค่ `js/tactics-core.js` (ระบบ v32 เดิม) และ `js/monster-animation.js` ที่อ่าน
- **ข้อเสนอ:** ต่อ difficulty เข้า HP/ATK ศัตรูตอนสร้างสนาม (`town-battle.js` จุดสร้าง `MON`) และต่อ speed เข้า `wait()` (`town-battle.js:88`), `walkAnim`, ระยะ hit stop · หรือถ้ายังไม่ทำ ให้ซ่อนตัวเลือกไว้ก่อน

### 3.2 [P1] สนามรบบนจอมือถือแนวนอน (844×390)
- แผงซ้ายกว้าง ~25% ของจอ, แผงข้อมูลบนขวาทับคิวเทิร์น, การ์ดบนมือเหลือครึ่งใบ — สนามที่มองเห็นเหลือราวครึ่งจอ
- ข้อมูลตัวเอกแสดงซ้ำ 3 ที่ (แผงซ้าย, กล่องบนขวา, การ์ดภาพเหมือนขวา)
- เบนช์มาร์ค (TS/FFT): จอหลักเป็นสนาม, ข้อมูลยูนิตโผล่เฉพาะตอนเลือก, เมนูคำสั่งเป็นรายการสั้นข้างตัวยูนิต
- **ข้อเสนอ:** โหมด "จอแคบ" (< 900px): ยุบแผงซ้ายเป็นแท็บ/ปุ่ม, รวมข้อมูลยูนิตเหลือกล่องเดียว, การ์ดบนมือเป็นพัดแบบเลื่อน

## 6. แผนปรับปรุงที่เสนอ (เรียงตามความคุ้มค่า)

**รอบ 1 — แก้เร็ว ผลชัด (≈ 1–2 วัน)**
1. เงาขอบขาวแบบแคช (ข้อ 2.2) + ย้ายจุดเกิดในตลาด
2. ต่อ difficulty/speed เข้าระบบต่อสู้ (ข้อ 3.1)
3. ซ่อม manifest `.png→.webp` + กันไม่ให้ Push เขียนกลับ + เทสต์ (ข้อ 4.2)
4. `AssetSize.key` ตัด base path + ย้ายค่า (ข้อ 4.1)
5. แก้เทสต์ที่ AI ทำพังเอง 2 ตัว + รันตัวสร้างดัชนี 2 ตัว + เพิ่ม `murk` (ข้อ 4.1)
6. ขยาย `test-version` ให้ตรวจทุกหน้า + bump `?v=` ที่ค้าง 14 ไฟล์ (ข้อ 2.8)
7. หน้าแรกไม่เรียก GitHub API สำหรับผู้เล่น (ข้อ 2.7)

**รอบ 2 — UI (≈ 2–3 วัน)**
8. ตัวอักษรขั้นต่ำ + คิวเทิร์นไม่ตัดชื่อ (ข้อ 3.3)
9. ป้ายชื่อหมู่บ้านไม่ถูกทับ, ไอคอนแผนที่โลกชุดเดียว, คำเดียวทั้งเกม, ซ่อนปุ่มผู้สร้าง, ธาตุเป็นไอคอน+ไทย (ข้อ 3.4)
10. โหมดจอแคบของสนามรบ (ข้อ 3.2)

**รอบ 3 — ประสิทธิภาพเชิงโครงสร้าง (≈ 3–5 วัน)**
11. โหลดหน้าแรกเบาลง < 10 MB (แยก manifest, หน่วง iframe) (ข้อ 2.3)
12. แคชเลเยอร์สนามรบ + mip ภาพ prop + occlusion เฉพาะตอนย้าย (ข้อ 2.4)
