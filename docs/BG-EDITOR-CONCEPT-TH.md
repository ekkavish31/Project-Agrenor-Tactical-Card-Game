> สถานะ: **ผู้ใช้อนุมัติ "ตามที่แนะนำ" (8 พ.ย. 2026)** · เฟส 1 ทำแล้ว v98.276 · **เฟส 2 ทำแล้ว v98.277** (BG Asset ไฟล์ + `?bg=` + คลัง + Push; ใช้ "seed + ชั้นการแก้ + ลายนิ้วมือ" แทนการแช่แข็งทุกช่อง — ถ้าตัวสร้างสนามเปลี่ยนจะเตือน) · เฟส 3–5 ยังไม่ทำ · คำตอบ: 1 = เลือก/ย้ายก่อน · 2 = BG Asset ชนิดเดียวกับ chunk · 3 = เกมสุ่มเลือกตามไบโอมได้ · 4 = ทดลองเล่นสำคัญรองจากแปรงพื้น · ผูกกับ TODO B10 / C5 / "Battleground Editor ไม่ได้ควบคุมฉากต่อสู้จริง"

## 1. ปัญหาของวันนี้ (ตรวจจากโค้ดจริง)
| ที่มา | ข้อเท็จจริง |
|---|---|
| ภาพที่ 1 (🎬 ฉากจริง) | เปิดฉากจริงสุ่มจากไบโอม+seed ใน iframe ดูได้อย่างเดียว ซูม/เลื่อน/คลิกแก้ไม่ได้ |
| ภาพที่ 2 (แก้ชิ้น) | วาดด้วยตัวเรนเดอร์ iso ของตัวเอง (`battleground.html`) หน้าตา/พื้นผิว/ต้นไม้ไม่ตรงฉากจริง |
| ที่เก็บ "ชิ้น" | `localStorage battleground-v1` → `tactics-core.js` (แล็บกริดเก่า) ฉากจริง (`field-host.js` + `town-battle.js`) **ไม่อ่าน** |
| ฉากจริงสร้างจาก | `FIELD.cells` (u,v,ชนิด,prop,seed) + แผนที่ความสูง/วัสดุจาก `T.forScene` + `FieldDiorama.landforms/structures` — ทั้งหมดเกิดจาก seed |

**ต้นเหตุ = มีตัวเรนเดอร์ 2 ชุด** → แก้ที่ต้นเหตุ: ให้ editor ใช้ตัวเรนเดอร์ฉากจริงตัวเดียว

## 2. แนวคิดหลัก
> **"WYSIWYG: แก้บนฉากจริง · เซฟเป็น BG Asset · ฉากจริงโหลดมาเล่น"**

1. **Editor = ฉากจริงในโหมดแก้ไข** (`battle-field.html?edit=1`) ใช้ `field-host.js` + `town-battle.js` ชุดเดียวกับเกม ไม่มีตัวเรนเดอร์ปลอมอีก
2. **BG Asset** = ไฟล์ข้อมูลหนึ่งสนาม `data/battlefields/<id>.json` (ขนาด · ไบโอม · ความสูง/วัสดุรายช่อง · ของวาง (prop) · จุดเกิดฝ่ายเรา/ศัตรู · เป้าหมาย · แสง/เวลา · ป้ายกำกับ · ภาพย่อ) + ดัชนี `data/battlefields/index.json`
3. **เกมโหลด BG Asset** ด้วย `?bg=<id>` หรือเลือกสุ่มจากชุดที่ติดป้ายไบโอม/ความยากตรงกับการต่อสู้นั้น (ไม่มี asset = สุ่มเหมือนเดิม จึงไม่พังของเก่า)
4. **ชิ้นเดิม (chunk)** ไม่ทิ้ง: เป็น "ชิ้นส่วนที่ประทับลงสนาม" ต่อไป และแปลงเป็นชนิดหนึ่งของ BG Asset ขนาดเล็ก (ดูเฟส 3)

## 3. ต้องทำได้ (ตามที่ผู้ใช้สั่ง)
- ซูมเข้า/ออก เลื่อนดู หมุนมุม 4 ทิศ (ใช้ปุ่มเข็มทิศเดิม)
- **คลิกเลือก · ลากย้าย · เปลี่ยน** ตัวละคร/ศัตรู/ของวาง บนฉากจริง (กล่องแสดงตัวที่เลือก มีมือจับย้าย หมุนทิศ ลบ ทำซ้ำ)
- ย้าย/เปลี่ยน asset (ต้นไม้ หิน รั้ว ซาก ฯลฯ) · แปรงสร้าง/แก้พื้น (ความสูง วัสดุ น้ำ ทางลาด บันได สะพาน)
- สร้างสนามใหม่ หรือ **"แช่แข็ง seed"** = เอาฉากสุ่มที่ชอบมาเป็นจุดเริ่มต้นแล้วแก้ต่อ → เซฟ BG Asset
- เซฟ/เก็บ/โหลดคลัง BG Asset · ภาพ BG Asset ในคลัง/แผงแก้ = ภาพจากตัวเรนเดอร์จริง (ถ่ายภาพย่อจากฉากจริง)

## 4. ไอเดียเพิ่มเติม (ให้ editor สมบูรณ์)
**ช่วยสร้าง**
1. สุ่ม→แก้: ปุ่ม 🎲 สร้างตามไบโอม+seed แล้ว "แช่แข็ง" เป็นสนามให้แก้ (ทางลัดสร้างสนามเร็ว)
2. แปรงขนาด 1×1 / 2×2 / 3×3 · เติมช่วง · สะท้อนซ้ายขวา/หมุนสมมาตร (ทำสนามแข่งสองฝั่ง)
3. คัดลอก/วาง/หมุน/พลิก "ส่วนของสนาม" (เลือกกรอบ) · ประทับชิ้น (chunk) จากคลัง
4. Snap เข้ากริด + ไกด์ (เส้นช่อง ความสูง ระยะเดิน/ระยะยิง ของตัวที่เลือก)
5. คลังของวาง: ค้นหา/กรองตามไบโอม ดูขนาดช่องที่กินและกล่องชน/การบัง (collision/occlusion) ของแต่ละชิ้น
**ตรวจคุณภาพ (Validator — ช่วยกันสนามพัง)**
6. ทุกช่องที่ควรเดินถึงต้องถึงได้จากจุดเกิด (ตรวจเส้นทาง) · ไม่มีจุดเกิดติดกำแพง · ของวางไม่ทับกัน
7. เตือนช่องที่ตัวละครถูกของบังหมด (occlusion) ตอนหมุนทุกมุม
8. วัดสเกลด้วยไม้บรรทัดตัวเอก 1.70 ม. (ใช้ `CharSize`) — ต้นไม้/ประตู/ผาเทียบกับตัวละครจริง
**ทดสอบ**
9. ▶ ทดลองเล่นในที่เดิม (ใส่ทีม+ศัตรู กด Auto ดู AI เดิน/สู้ แล้วกลับมาแก้ต่อได้ทันที ไม่ออกจากหน้า)
10. จำลองสมดุลเร็ว: รัน `simulate` 100 รอบบนสนามนี้ → ชนะ % / เทิร์นเฉลี่ย / จุดที่ตายบ่อย
11. ดูแบบแสงกลางวัน/กลางคืน/ฝน (ตัวแปรเดียวกับฉากจริง)
**จัดการ/ส่งต่อ**
12. ป้ายกำกับ ไบโอม · ขนาด · ความยาก · ประเภท (ฝึก/สุ่ม/บอส/เนื้อเรื่อง) + ช่วงเลเวลที่เหมาะ
13. เวอร์ชัน/ประวัติ (กู้ย้อนได้) · Undo/Redo ลึก · ตัวเลือก autosave ในเบราว์เซอร์ก่อน Push
14. Push ขึ้น GitHub ด้วยระบบเดิม (`GitHubPush`) · ส่งออก/นำเข้าไฟล์ · ลิงก์ตรง `?bg=<id>` ไว้ทดสอบ
15. บอกว่า BG Asset ไหน "ถูกใช้ที่ไหน" (ฉากเควสต์ไหน/บอสไหน) — เชื่อมกับ 📋 Asset Manager

## 5. สิ่งที่จะทำก่อน (ขอบเขตเฟสแรก — MVP)
| เฟส | ส่งมอบ | ตรวจรับ |
|---|---|---|
| **1 · ดูและเลือกบนฉากจริง** | `battle-field.html?edit=1`: ซูม/เลื่อน/หมุน · คลิกเลือกตัวละคร/ของวาง · ลากย้าย/หมุนทิศ/ลบ/ทำซ้ำ · แผงคุณสมบัติ · Undo/Redo | ย้ายต้นไม้กับตัวละครได้ แล้วเซฟ/โหลดซ้ำได้ตรงเดิม |
| **2 · BG Asset + เกมโหลดได้** | เซฟ `data/battlefields/<id>.json` + ภาพย่อจากฉากจริง · คลังใน editor · `?bg=<id>` · "แช่แข็ง seed" | เปิด `?bg=` แล้วฉากตรงกับที่แก้ · ไม่มี `bg` = สุ่มเหมือนเดิม · e2e ผ่าน |
| **3 · แปรงพื้นและชิ้นส่วน** | แปรงความสูง/วัสดุ/น้ำ/ทางลาด/บันได/สะพาน · คัดลอก/วาง/สะท้อน · ประทับ chunk เดิม | วาดภูเขาเล็ก ๆ แล้วเดินขึ้นได้จริงในการต่อสู้ |
| **4 · ตรวจและทดลองเล่น** | Validator (ถึงได้/ชน/บัง) · ▶ ทดลองเล่นในที่เดิม · ไม้บรรทัดสเกล | สนามที่ตรวจไม่ผ่านขึ้นเตือนก่อนเซฟ |
| **5 · คลังและการใช้งานในเกม** | ป้ายกำกับ · เลือกสนามให้เควสต์/บอส · ประวัติเวอร์ชัน · สถิติสมดุล · ผูก Asset Manager | เควสต์/บอสเลือก BG Asset ได้ |

## 6. ความเสี่ยงที่ต้องรู้
- ตัวฉากจริงตอนนี้ **สร้างแล้วเรนเดอร์เลย** (ยังไม่มีขั้น "ข้อมูลสนาม → เรนเดอร์" ที่แยกกัน) เฟส 1–2 ต้องผ่าตัดให้ `FIELD.cells` + แผนที่ความสูงเขียน/อ่านเป็น JSON ได้ — นี่คือส่วนยากสุด
- ความสูง/ทางลาดอยู่ใน `tactics-terrain`/`FieldHeight` ต้องไล่ว่าเก็บอะไรบ้างจึงสร้างซ้ำได้ตรงเป๊ะ (ทดสอบด้วย "เซฟ→โหลด→เทียบภาพ/ข้อมูล")
- ต้องไม่ทำให้ฉากสุ่มเดิมพัง → มีเทสต์ (`tools/e2e-game-flow.cjs` + เทสต์ใหม่เทียบ seed เดิมได้ผลเดิม)
- BG Asset ใหญ่ขึ้นตามขนาดสนาม → เก็บแบบบีบอัด (รายช่องเป็นสตริง/RLE) ไม่ใช่ JSON ต่อช่อง

## 7. คำถามที่ต้องให้ผู้ใช้ตัดสิน
1. เฟสแรกเริ่มที่ "เลือก/ย้ายของบนฉากจริง" (แนะนำ) หรือ "แปรงพื้นก่อน"?
2. BG Asset เป็นคนละชนิดกับ chunk (สนามทั้งผืน) หรือ **ชนิดเดียวกัน ต่างกันแค่ขนาด** (แนะนำ: ชนิดเดียว ง่ายต่อการประทับ)
3. สนามที่เซฟแล้วให้เกมสุ่มเลือกใช้เองตามไบโอม หรือ **ต้องผูกกับเควสต์/บอสเท่านั้น**?
4. ทดลองเล่นในที่เดิม (เฟส 4) สำคัญกว่าแปรงพื้น (เฟส 3) ไหม?
